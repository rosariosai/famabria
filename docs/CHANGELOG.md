# Famcal changelog

| Version | What changed |
|---|---|
| 2.9.1 | Device name: new devices are called «PC di …» in the extension and «Telefono di …» on the web app; ✎ next to «Questo dispositivo» renames it. Reminder script: starts without FAMABRIA_INVITE once the v2 invite was redeemed. |
| 2.9.0 | **No more double members.** The same person listed twice (same name, different ids, e.g. two devices each created «Anna») is merged automatically on every device, notes included; the smaller id wins so all devices agree. A new install now gives its first member a unique id instead of «personal», so two devices can no longer collide. |
| 2.8.3 | Fix: the «Sposta le sue note in» chooser was squeezed into a 36 px column; it now spans the whole member row. |
| 2.8.2 | A member that only exists because of deleted notes (e.g. a stray «Membro») no longer comes back after being removed. |
| 2.8.1 | Impostazioni → Membri: **Rimuovi** su un membro con note propone di spostarle su un altro membro (per sistemare i membri doppi); sposta tutte le note di un membro in un altro (per sistemare i membri doppi) e toglie il membro svuotato. |
| 2.8.0 | **Modalità SOLO**: scelta al primo avvio («Solo io» / «Con la famiglia») e in Impostazioni → Modalità; in SOLO sono nascosti Famiglia, Server di casa, Membri e legenda. Entrare in una famiglia passa a condiviso da solo. Il nome della famiglia si cambia con ✎ (solo su quel dispositivo). Stato «Sincronizzata» al posto di «Aggiornata»; ⚙ senza testo; elenco dispositivi con i nomi. |
| 2.7.0 | **Dispositivi** in Famiglia (solo per chi ha creato la famiglia): elenco di chi ha accesso e pulsante **Rimuovi** (il dispositivo perde subito l'accesso e il suo file viene cancellato). Relay: `GET /v1/f/<family>/devices` (admin). |
| 2.6.0 | **Copia di sicurezza** (Impostazioni: salva/ripristina tutte le note e i nomi dei familiari, senza chiavi). **Passa alla famiglia sicura** (migrazione di una famiglia con link permanente a una v2: le note restano sul dispositivo e vengono inviate alla nuova famiglia). **Invito per il server di casa** (ruolo bot, sola lettura). The reminder script understands v2 invites (redeems once, keeps its own read-only credentials in the state file, renews its token). Bots renew their 90-day token. |
| 2.5.1 | Device tokens of v2 families last 30 days and renew themselves automatically (when less than 15 days are left, at sync time). Relay: `POST /v1/f/<family>/token/refresh`. A device offline for more than 30 days needs a new invite. |
| 2.5.0 (name) | The app is now called **Famabria** (screens, texts, manifest, docs). Technical names stay `famcal` on purpose so nothing existing breaks: Worker `famcal-relay` and its web address, IndexedDB `famcal`, encryption labels, `.fc` files, extension id, file names. Renaming the Worker/address is a separate, later decision (it changes every invite and installed app). |
| 2.5.0 | New families created on the Cloudflare relay use signed device tokens and **one-time invite links** (valid 15 minutes, work once, never contain the family key). Existing families keep working with their old link. The old invite link keeps working for old families only. Reminders on the home server still read old families only. |
| Relay (unreleased) | New `/v1` relay API with signed device tokens: tokens are verified before a Durable Object is created, oversized uploads are refused before buffering, a device can only write its own `d-<id>.fc`, admins can issue/revoke device tokens, per-device rate limit. Legacy `/r/*` unchanged. Needs the `TOKEN_SECRET` Worker secret. One-time invites (15 min, 5 tries, no admin role) added on the relay side; the apps do not use them yet. |
| 2.4.0 | A device that joins a family now receives the family's member names and colours as a starting point (members it does not have yet, or still shows as "Membro"). Names and colours chosen on a device are never overwritten: they stay per device. |
| 2.3.2 | Invite links made from the extension now point to the web app on the relay (https://…/app/app#join=…) instead of chrome-extension://…, so they open on any phone. |
| 2.3.1 | New Famcal logo for the extension and the web app. "10 minutes before" is no longer offered as a reminder (the home server checks once an hour); old notes that have it still work. |
| 2.3.0 | Reminders now go through ntfy, sent by a small program on the home server (server/reminders): the note form has "Promemoria" again (none / at the time / 10 min / 1 hour before / evening before), notes with a reminder show the horn icon. The app and the extension no longer notify by themselves. The program reads the family's encrypted notes from the relay (Cloudflare or home) as a read-only device, so Cloudflare and the home server work together. |
| 2.2.1 | Notes with a reminder show a small horn-speaker icon (month, week, day panel, search). |
| 2.2.0 | Reminders for notes (none / at the time / 10 min / 1 hour before / evening before): in-app banner and system notification on the web app (while it is open), alarms + notifications in the extension even with the calendar closed. Phone-to-phone QR sharing removed (Famiglia replaces it). |
| 2.1.1 | The old "Sync" (home server) button is gone from the toolbar unless a home server is already connected; it lives in Impostazioni → Server di casa (avanzato). First run and welcome always lead to Famiglia. |
| 2.1.0 | Offline: the web app opens without network (service worker), notes are written on the device and the family sync resumes when the network returns. Note form follows Stitch 06/07/08 (all-day switch, error under the title, "Modificata da…" line, Elimina nota, "Nota eliminata · Annulla" toast). Selected day in the week view is no longer clipped. |
| 2.0.1 | Week view: one day per row on every screen (day on the left, its notes on the right on wide screens). |
| 2.0.0 | Week view (Mese / Settimana switch): seven days side by side on desktop, a list on phones; ‹ › and swipe move by week. |
| 1.9.1 | The side-panel layout now starts at 1000 px (was 1180), so zoomed Windows screens also get it; 1000–1179 px shows the members in a row on top. |
| 1.9.0 | Desktop (1180 px and wider): the note form lives in the side panel (no pop-up); clicking a day selects it and focuses the title. Phones keep the bottom sheet. |
| 1.8.1 | App opened from the Cloudflare address no longer asks for a home-server token: it opens Famiglia instead (and hides the home-server button). |
| 1.8.0 | The Cloudflare deploy now also serves the web app (same address as the relay), so phones need no home server; the relay address is pre-filled when the app is opened from workers.dev. |
| 1.7.10 | Icon colours: red C on white background. |

| 1.7.7 | Server-di-casa dialog fully in Italian; phone toolbar compacted; strips on by default on phones. |
| 1.7.6 | The version is shown at the bottom of Impostazioni. |
| 1.7.5 | Desktop layout (1180 px and wider): members on the left, month in the centre, "Giorno selezionato" panel (340 px) on the right with the day notes and a New note button; toolbar and hints in Italian. |
| 1.7.4 | Note sheet in Italian with member chips and the "Scrivi un titolo o una nota" message; a note is no longer dropped from the screen when a refresh races with saving, and a failed write now shows an error instead of failing silently. |
| 1.7.3 | Saving a note for a member that is hidden in the legend now shows that member again (the note used to be saved but stay invisible, which looked like "cannot save"). |
| 1.7.2 | **Saving a note is now obvious and errors are visible.** The note dialog closes after Add/Save (the note shows on the day row); if saving fails a red message with the reason appears instead of silence. |
| 1.7.1 | **Cloudflare relay reworked for the free plan.** KV allows only ~1000 list calls/day (a tablet polling every 5 min would use it up), so the Worker now keeps one Durable Object per family (strongly consistent, no list quota). `relay/wrangler.toml`, `npm run deploy:relay` / `dev:relay`, object limit 1 MB. Verified in `wrangler dev` (workerd) with the real client. Guide `docs/RELAY.md` rewritten as a beginner step-by-step (account, `npx wrangler login`, `npx wrangler deploy`, check, create family), with the same steps inside the app (collapsible "Come si crea…" in Famiglia for relay and Dropbox). |
| 1.7.0 | **Provider C: Dropbox as the family mailbox.** "Crea con Dropbox" (web app, PKCE sign-in once on a shared family account, folder `Apps/Famcal`); the invite link carries the access so relatives join with one tap; joining from the extension now asks the browser for access to the invite's service (also fixed for relay invites). New `src/cloud/dropbox.ts`, `docs/DROPBOX.md`. Needs the owner's Dropbox App key. 4 new tests with a fake Dropbox. Google Drive and the Cloudflare relay deployment come next. |
| 1.6.0 | **Famiglia: sync automatico con un invito (setup in ~3 minuti, poi niente più QR).** Ogni dispositivo scrive solo il proprio oggetto cifrato (AES-256-GCM, chiave nel link di invito dopo `#`) in una "cassetta" muta (relay Cloudflare Worker/Node); gli altri lo leggono e fondono: nessun conflitto di scrittura. Sync all'apertura, al ritorno sulla scheda, ogni 5 min e 2,5 s dopo una modifica. Dialog "Famiglia" (crea, copia/condividi link, entra con link incollato o aprendo `#join=`, esci). Provider-agnostico (`Mailbox`): Dropbox/Drive si aggiungono dopo. Relay in `relay/` (`npm run build:relay`), guida in `docs/RELAY.md`. Testato: 6 test + e2e browser con due telefoni simulati. |

| 1.4.0 | **Phone-to-phone sharing without a server** (first slice): pair two phones with two QR codes + control code, exchange notes in an encrypted `.famcal` file (send / receive / unlink). See `P2P-SHARING.md`. Live WebRTC sync is the next step. |
